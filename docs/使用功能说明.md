## 1. 这个工具能做什么

把图片的背景去掉，输出**透明背景的 PNG**，方便叠到任何其它背景上使用。

| 能力 | 支持情况 |
| --- | --- |
| 去除白色背景 | ✅ |
| 去除黑色背景 | ✅ |
| 去除其它纯色背景（灰、蓝、绿…） | ✅ |
| 自动识别背景类型 | ✅ |
| **精细抠图（默认）：复杂背景用大模型（BiRefNet 1024×1024），发丝/飘带/细长道具都留得住** | ✅ v1.5 新增 |
| AI 提取复杂背景（渐变/纹理/实景照片）的主体 | ✅ 本地模型，离线 |
| 混合模式：白色衣服/头饰等与背景同色的部件自动保留 | ✅ |
| 手动抠图：矩形框 / 点选 / 描边 / 套索 | ✅ 四种都有 |
| **点选 = 笔刷涂抹**（按住拖动，想留哪块就涂哪块） | ✅ v1.3 增强 |
| **一次描多个互不相连的区域** | ✅ v1.2 新增 |
| **框内保留 / 框内去除（人工裁决）** | ✅ v1.2 新增 |
| **GrabCut 自动抠图（独立按钮）** | ✅ v1.3 改造 |
| **处理完只显示结果，绿/红标注默认不残留** | ✅ v1.3 修正 |
| **画质：浅色内部部件（眼睛高光、白围裙等）不再发灰/半透明** | ✅ v1.4 修复 |
| **画面缩放 / 中键拖动平移 / 逐级撤销** | ✅ v1.2 新增 |
| **画布流畅**（放大到看清单个像素也不卡，Qt 视口裁剪） | ✅ v1.8 迁移 QGraphicsView |
| **重写（Redo）**：撤销后悔了，可按 Ctrl+Y 找回 | ✅ v1.8 新增 |
| **ROI 局部处理**：框一块只重跑这一块，框外不动 | ✅ v1.8 新增（用法见 3.10） |
| **描边顶点固定小点**：放大到像素级细描也不挡视线 | ✅ v1.9 修复 |
| **点选笔刷可细到 1 像素** | ✅ v1.9 修复 |
| 处理单张图片 | ✅ |
| 批量处理整个文件夹 | ✅ |
| 输入已是透明 PNG 时直接沿用，不破坏原图 | ✅ |
| Windows 桌面窗口（点鼠标操作） | ✅ |

**这是一个完整的桌面软件**：有图形界面，双击即可用。

## 2. 启动方式

### 方式 A：桌面窗口（推荐）

在项目目录下运行：

```bash
.venv\Scripts\python.exe -m src.app
```

或直接用 PyCharm 打开 `src/app.py` 右键 Run。

启动后会出现窗口，左侧是操作区、右侧是原图和结果预览。

### 方式 B：命令行

```bash
.venv\Scripts\python.exe -m src.main -i 图片.jpg -o 输出.png
```

不带参数运行会弹出文件选择框（`python -m src.main`）。

### 方式 C：打包成 exe（双击即用）

```bash
.venv\Scripts\python.exe -m PyInstaller build.spec --clean
```

打包完成后在 `dist/LucentCut.exe`，双击即可运行，**无需安装 Python**。

## 3. 桌面窗口怎么用

### 3.1 处理一张图

1. 点「打开…」选一张图（或直接把图片文件**拖进窗口**）；
2. 在「处理方式」里选引擎（**默认「精细抠图」通常就是最佳选择，一般不用改**）：
   - **精细抠图（matting，默认）**：复杂背景（渐变、纹理、实景照片、动漫合影）会用
     大模型（BiRefNet，1024×1024）抠，**头发丝、飘带、细长道具（剑、发饰）都能留住**；
     纯色背景会自动改用颜色键控（很快，0.2~0.3 秒）；模型文件缺失时自动回退。
     **代价是慢**：复杂图单张约 8~17 秒（本机 CPU），请耐心等；
   - **混合**：先按颜色抠轮廓，再用 AI（u2netp）把"和背景同色、被误删的主体部件"
     （白色裙子、白色衣领、白色头饰等）补回来。比精细抠图快很多，适合对发丝精度要求不高时；
   - **颜色键控**：适合干净的白底/黑底/纯色底，最快，但白底上的白色衣服会被一起抠掉；
   - **AI 语义分割**：只用 u2netp，适合复杂背景但不需要发丝级精度的场合；
     AI 不可用时会给出具体原因。
3. 点「开始处理」；
4. 右侧「结果」栏显示抠好的图，底板可在「预览底板」里切换（红色底板最容易看出残留白边）；
5. 点「保存结果」导出 PNG（或在「另存为…」指定路径）。

**左下角有进度条和计时（v1.6 新增）**：处理中进度条会动——单张是流动指示
（大模型推理没法精确到百分比），**批量处理则精确显示"第几张 / 共几张"**；
旁边的计时实时跳动，完成后定格为"上次处理耗时：X.X 秒"，状态栏也会显示总耗时。

### 3.2 视图操作（缩放 / 平移）

描边前先把画面调舒服，这一步能省很多事：

| 操作 | 效果 |
| --- | --- |
| 鼠标滚轮 | 以光标位置为中心缩放（放大后描边更精准） |
| **按住鼠标中键拖动** | **平移画面** |
| Ctrl + 左键拖动 | 平移画面（没有中键的触摸板用这个） |
| Ctrl + 0 或「适应窗口」按钮 | 整图缩放到刚好铺满预览区 |

> **平移不会弄乱你画的东西。** 你描出的点全部按**原图坐标**保存，
> 拖动画面只是改变看到的区域，已经画好的线和区域会跟着画面一起走，不会错位、不会被清空。

换底板、重新处理时视图也保持不动，方便你放大盯着同一处边缘反复对比。

### 3.3 手动抠图：五种绘制工具

右下角第一行是**绘制方式**，选一种在结果图上画：

| 工具 | 操作 | 适用 |
| --- | --- | --- |
| **预览** | 不做绘制；**点击即清除画布上的 ROI 框与未提交的选区/涂抹** | 回到干净的结果预览 |
| 矩形框 | 按住左键拖一个框 | 主体和背景颜色差异明显 |
| **点选** | **按住左键拖动涂抹**（涂当前作用色），按住右键涂反面 | 精细指定：眼白、高光、纽扣这种小块 |
| 描边 | 左键依次点出多边形顶点，**双击 / 右键**闭合这一块 | 形状不规则、要贴着轮廓走 |
| 套索 | 按住左键自由画一圈，松开闭合 | 随手圈选 |
| **ROI 区域**（v1.8 新增） | 拖一个框，再点「开始处理」 | **只重新处理框内**，框外不动，见 3.10 |

**点选就是一支笔刷**：笔尖大小由左侧参数「**点选笔刷半径**」控制（默认 12 像素）。
按住左键一路拖过去就涂出一整片，不用一个点一个点点。
左键涂的是「作用」里选的那种（默认**保留**），**右键涂反面**——所以一笔画里
既能补（绿）又能删（红）。

**描边顶点是个小点，放大也不会变大**（v1.5 起）：描边时常需要把画面放大到能看清
单个像素再细描，所以顶点的圆点是**固定屏幕大小（约 3 像素）**——无论放到多大，
它都只是一个小点，不会盖住你要对齐的那几个像素。**套索**同样如此。

> 为什么改成笔刷？因为点选的语义应该是"**我说这块要留下，它就必须留下**"，
> 而不是"让算法去猜"。旧版点选是把几个点交给 GrabCut 做全局分割，
> 点少的时候会猜偏（甚至把整张图算没），现在完全按你涂的范围精确生效。

### 3.4 一次描多个区域（v1.2 新增）

描边和套索**不再只能画一块**。闭合一块之后它会被留在列表里，你可以接着画第二块、第三块，
彼此互不相连也不会被一条线串起来。

- 闭合当前这块：**双击** 或 **右键**；
- 画完所有块之后：按 **Enter** 或点 **「✔ 应用选区」** 一次性生效；
- 状态栏会实时显示「已画 N 个区域」，不用猜有没有画上。

典型用法：一个角色有两处需要保留（比如头饰和裙子），一次画两块再一起应用。

### 3.5 撤销（v1.2 新增）

按 **Ctrl + Z** 或点 **「↶ 撤销」**，分三级往回退：

1. 正在涂/正在画的这笔 → 退掉最后一个点；
2. 已经闭合的块 → 整块退回草稿状态（**不是直接丢掉**，可以接着改）；
3. 都没有了 → 撤销上一次**已经生效**的修改（包括算法结果和保留/去除裁决）。

画错了不用「清空选区」从头再来。

### 3.6 框内保留 / 框内去除（v1.2 新增，v1.3 调整）

第二行的「**作用**」下拉框只有两项，它决定你画的每一笔是什么意思：

| 作用 | 说明 |
| --- | --- |
| **保留（画的地方一定留下）** | 你画到的像素**无条件变成不透明**，算法再怎么判都不许删 |
| **去除（画的地方一定去掉）** | 你画到的像素**无条件变成透明**，用来清掉没去干净的背景残留 |

**这就是「白色衣服 / 眼白被一起去掉」的解决办法**：处理完之后，把工具切到「点选」
（或「描边」「套索」），「作用」选「保留」，在丢掉的地方涂/圈一下，按 Enter ——
那块立刻回来，而且**颜色取自原图**，不会被算法留下的脏色污染。

几个要点：

- **后画的覆盖先画的**（v1.6 修正）：同一块地方先画「保留」、再画「去除」，
  以**后画的**为准——想反悔随时反悔，两个方向都行；
- **同一笔里**既涂了保留又涂了去除（点选左键+右键混着涂）且重叠时，以保留为准（防误删）；
- **点选的颜色在涂下那一刻就定好了**：绿=保留、红=去除。之后改「作用」下拉
  不会改变已涂点的效果；矩形框/描边/套索圈出的区域则按**提交那一刻**的「作用」处理；
- 画完涂抹**忘了按 Enter 就点了「开始处理」**也没关系——涂抹会自动生效，不会丢；
- 想回到纯算法结果，点「清除手动修改」；
- 点选涂出来的形状是圆的，半径由「点选笔刷半径」决定；描边/套索/矩形框则是你圈的形状。

#### 关于「先处理还是先描边」（这里由我们拍板，规则如下）

> **裁决层独立于算法保存，永远最后叠加，优先于算法。**

具体意思是：

- 你可以先「开始处理」，再涂保留，再点一次「开始处理」——**保留依然有效**，不会被冲掉；
- 裁决始终作用于**最新一次**的算法结果（换引擎、换参数重新处理都照样生效）；
- 保留区如果被算法判成了背景，颜色会用**原图 RGB** 填回来（拿回衣服本来的颜色，
  而不是算法留下的灰/黑）；
- 换一张图会清空裁决层（它是针对当前这张图的）；
- 批量处理不会套用当前这张图的裁决层。

### 3.7 三个执行入口：应用选区 / GrabCut / 显示修改区（v1.3 新增）

第二行按钮各自干什么：

| 按钮 | 作用 |
| --- | --- |
| **✔ 应用选区 (Enter)** | 把你**画好的**涂抹/区域按当前「作用」**直接生效**。不做算法计算，涂到哪就影响哪，立刻看到结果 |
| **↶ 撤销 (Ctrl+Z)** | 撤销上一步（先退画布上没生效的笔迹，再退已生效的修改） |
| **↷ 重写 (Ctrl+Y)** | **恢复**刚刚被撤销掉的内容（v1.5 新增，见 3.10） |
| **GrabCut 自动抠图** | 用你画的区域当线索，让算法**重新算一遍整张图**。适合"整张图都要重抠" |
| **清空选区 (Esc) / 清除手动修改 / 清 ROI** | 清掉还没生效的线 / 清掉所有已生效的保留去除 / 清掉 ROI 框选 |
| ☐ **显示修改区**（默认**关闭**） | 勾上才用绿(保留)/红(去除)标出你改过的位置 |

> **「应用选区」不是"自动抠图"。** 它只是把你画的保留/去除**直接盖章生效**，
> 所以涂哪儿就改哪儿，绝不会把没涂的地方弄没。
> 早期版本把它和 GrabCut 混在一个下拉框里，默认又是 GrabCut，
> 于是"点几个点再应用"会触发一次全局分割，把整张图算成透明（就是之前反馈的"全图变红"）——
> 现在两者彻底分开了，**GrabCut 变成一个需要单独点的按钮，且必须先画出区域**，
> 没画区域时它只会提示、什么都不做。

**处理完为什么看不到绿色了？** 因为「显示修改区」默认是关的。结果画面上只留结果本身，
想回看自己标过哪里，勾上那个勾选框即可（再取消勾选就又藏起来）。

### 3.8 批量处理

点「批量处理目录…」选一个文件夹，会把里面所有图片处理完，输出到该文件夹下的 `output/` 子目录。

### 3.9 重写（撤销后反悔 · v1.8 新增）

画错了按 **Ctrl+Z** 撤销，但如果你**撤多了**、想把刚撤销的内容找回来，就点 **「↷ 重写 (Ctrl+Y)」**。

- 例子：点选了一笔 → 觉得画错 → Ctrl+Z 撤销 → 又想留着 → 点「重写」→ 这笔点选**原样恢复**。
- 规则和大多数软件一致：**撤销之后如果又画了新内容，之前的重写记录就作废**（不能再重写回来了）。
- 撤销/重写同时覆盖两类内容：① 画布上**还没生效**的笔迹；② 已经「应用选区」**生效过**的修改。

### 3.10 只处理一块区域（ROI 局部处理 · v1.8 新增）

**场景**：整张图大体没问题，但**某一块背景没去干净**，你又不想用描边/点选一个个抠。

**做法**：

1. **先点一次「开始处理」**，得到整张图的结果（ROI 需要以这次结果为底板）；
2. 点「绘制：」里的 **「ROI 区域」** 按钮；
3. 在结果图上**拖一个框**，框住那块需要重新处理的地方（框是**琥珀色虚线**）；
4. 再点 **「开始处理」**。

此时程序会**只在框内**用当前引擎重新计算，**框外保持上一次的结果**一个像素都不动。
框的边界会做轻微羽化，不会出现生硬的接缝。

> ⚠️ **必须先处理过一次再框 ROI。** 如果图刚打开、还没处理过就框 ROI 再点「开始处理」，
> 程序会**按整张图处理**（ROI 不起作用）——因为这时还没有"上一次结果"可以当框外底板。

- **只保留一个框**：重新拖框会替换掉旧框。
- **取消框选**：点 **「清 ROI」**，之后「开始处理」又恢复为处理整张图。
- **处理完成后，黄框会自动消失**（说明这次的 ROI 已生效）；想再框一块重新拖即可。
- ROI 与普通选区（保留/去除）**互不影响**：可以先用 ROI 框一块重跑，再用点选微调。
- 引擎照常在整图上做推理（模型需要整体上下文），但**最终只采纳框内的新结果**。

## 4. 参数详解（什么时候调大、什么时候调小）

> 参数都在左侧「参数」区，改完点「开始处理」重新生效。
> **默认 30 / 80 / 0 / 0 / 0 / 1 / 12 对大多数图都合适，先别急着动。**
> 真要调，先按第 4.8 的「症状 → 怎么调」速查表定位。

先理解一件事：程序给每个像素算一个「与背景色的色差」（RGB 空间里的直线距离，
范围大约 0 ~ 441，0 = 和背景一模一样），再按下面这两个阈值决定它是背景还是主体：

```
色差 ≤ 下界          → 完全透明（判为背景）
下界 < 色差 < 上界   → 半透明（过渡带，决定边缘柔不柔）
色差 ≥ 上界          → 完全不透明（判为主体）
```

### 4.1 软阈值下界（默认 30）

**是什么**：色差小于这个数就算背景。

**调大**（如 40~70）→ 判定"算背景"的标准放宽 → **删得更多更狠**。

- 该调大的时候：背景不干净（轻微渐变、JPEG 噪点、扫描件脏点、纸张纹理），
  抠完周围还留着一层背景色的薄雾；或者主体的投影/浅色雾边没去掉。
- 调太大的后果：主体上凡是接近背景色的部分一起遭殃——白底上的白色衣服、浅灰高光、
  淡色阴影会被抠出洞。

**调小**（如 10~20）→ 判定更严格 → **只删和背景几乎一模一样的像素**，更保守。

- 该调小的时候：主体上有浅色部件被误删了，而背景其实很干净。
- 调太小的后果：背景残留、边缘留一圈脏点，主体外面像长了毛刺。

> **建议**：误删主体时，优先用「框内保留」把那块描出来，而不是一味调小下界——
> 调小会让整张图的背景都去不干净，属于"为了一棵树毁掉整片林"。

### 4.2 软阈值上界（默认 80）

**是什么**：色差大于这个数就算实心主体。**上界与下界之间的差值就是过渡带宽度**。

**调大**（如 100~140）→ 过渡带变宽 → **更多像素处于半透明，边缘更柔和**。

- 该调大的时候：主体边缘本来就是柔和的——毛发、羽毛、发光边缘、
  卡通图的抗锯齿描边。调大后边缘有自然的半透明渐变，不会出现"贴纸感"。
- 调太大的后果：主体边缘发虚、轮廓变胖，去白边后可能残留一圈半透明的雾。

**调小**（如 40~60）→ 过渡带变窄 → **边缘更硬更干脆**。

- 该调小的时候：抠完发现主体周围浮着一圈半透明光晕/雾，或者想要干脆利落的硬边。
- 调太小的后果：边缘出现锯齿（尤其斜线和圆弧），失去抗锯齿的平滑感。

**硬性约束**：上界必须大于下界，否则程序会直接报错拒绝处理。
两者差值建议至少留 20，太小过渡带几乎不存在，边缘会硬得发脆。

### 4.3 羽化半径（默认 0 = 自动）

**是什么**：对整张 alpha 做一次高斯模糊，让边缘平滑。
`0 = 自动`：短边 ≤ 64 像素的极小图自动取 0（避免小图被糊成一团），其它图取 1。

**调大**（2~3）→ 边缘更柔。

- 该调大的时候：照片、毛发、需要柔和过渡的图；或者主体边缘的锯齿很明显。
- 调太大的后果：主体像"瘦身"了一圈，细节圆角变糊，小图上尤其明显。

**调小 / 设 0** → 保留硬边。

- 该设 0 的时候：像素画、图标、文字 logo、贴纸——任何需要锐利边缘的内容。

### 4.4 收缩像素（默认 0）

**是什么**：把 alpha 整体向内腐蚀 N 个像素。

**调大**（1~2）→ 主体向内缩一圈。

- 该调大的时候：把「预览底板」切到**红色**，看到主体边缘泛着一圈白边（去白边没去干净）；
  或者 JPEG 压缩很重、边缘有背景色光晕。调到 1~2 通常就能吃掉。
- 调太大的后果：主体变小一圈，细线条（发丝、触须、细绳、小字）会断掉、消失。

**保持 0**：绝大多数情况，以及主体有大量细部时。

### 4.5 去噪最小面积（默认 0 = 关闭）

**是什么**：面积小于这个像素数的前景块，整块当成噪点删掉。

**调大**（按图幅给值：小图 30~80，中等图 100~300，大图 500~1000）

- 该调大的时候：背景上有杂乱噪点/污渍，抠完在空白处留下很多细碎斑点。
- 调太大的后果：主体本身的小碎块（耳饰、纽扣、远处的小元素）也被一起删掉。

**保持 0**：主体本身由很多零散小部件组成时不要开。

### 4.6 手动区边缘柔化（默认 1）

**是什么**：只影响你手工描的「框内保留 / 框内去除」区域的**边界**，不影响算法自己抠出来的边缘。

- **0 = 硬边**：描的形状精确生效，边界干净利落。像素图、图标、描得很贴的情况选这个。
- **1（默认）**：边界有 1 像素渐变，看起来不生硬，推荐默认。
- **2~3**：描得很粗糙、希望边界不要太扎眼时用。

> 无论调多大，**区域内部始终是满值**（保留区内部一定是 255 不透明），
> 只有最外圈会被柔化，不会出现"说是保留、其实半透"的情况。

### 4.7 点选笔刷半径（默认 12 像素）

**是什么**：用「点选」涂保留/去除时，**每一笔覆盖多大的圆**。单位是**原图像素**，
所以放大画面再涂，笔尖的"实际大小"不会变。

**调大**（20~40）→ 一笔覆盖更大范围。

- 该调大的时候：要救的部件比较大（整条白裙子、大片背景残留），不想涂半天；
  或者图片本身分辨率很高（4000px 以上），12 像素相对太小。
- 调太大的后果：一不小心就涂到旁边的背景上，把不该留的东西也保留了。
  这时按 **Ctrl+Z** 撤销重来。

**调小**（**1~8**）→ 一笔更精细。最小可以设到 **1 像素**（几乎逐个像素级）。

- 该调小的时候：处理眼白、高光、纽扣、小饰品这种很小的细节；或者要贴着边缘精确修补。
  小笔刷 + 放大画面（滚轮）是最精细的组合。
- 提示：半径会**严格按你设的值**生效（设 2 就是 2 像素），放大画面时屏幕上看大，
  是因为整体被放大了——笔尖对应的原图像素范围没有变。

**怎么判断该多大**：目测目标区域的宽度，取它的 **1/3 ~ 1/2** 差不多。
宁可小一点多涂两笔，也别一大笔糊到背景上——涂多了要撤销，涂少了补一笔就行。

> 笔刷影响的是**点选**；矩形框/描边/套索不受它影响，圈多大就是多大。

## 5. 结果怎么看

### 5.1 模式（状态栏里显示的那个词）

| 模式 | 含义 |
| --- | --- |
| `white` | 按白底处理 |
| `black` | 按黑底处理 |
| `solid` | 按其它纯色底处理（灰、蓝、绿等） |
| `reuse` | 输入已经是抠好的透明图，直接沿用（不重抠） |
| `matting` | 精细抠图引擎：复杂背景用 BiRefNet 大模型抠（头发丝/细长道具清晰） |
| `hybrid-white` / `hybrid-black` / `hybrid-solid` | 混合引擎：颜色轮廓 + AI 补齐，中划线后是识别出的背景类型 |
| `ai` | 纯 AI 语义分割提取主体（u2netp；复杂背景会自动走到这里） |
| `manual-matte` | 点了「GrabCut 自动抠图」的结果 |

> 注意：选「精细抠图」但**背景是纯色**时，状态栏会显示 `hybrid-white` 等——
> 这是**有意为之**：纯色底的颜色键控轮廓比任何语义分割都贴合原始像素，
> 又快又准。想强制走大模型，可先把背景换成复杂图，或改用「AI 语义分割」。

> 用「应用选区」做的保留/去除**不改变模式名**——它只是在算法结果上叠了一层裁决，
> 状态栏会额外提示「已叠加手动修改」。这样能一眼看出"这张图底层是哪个引擎抠的"。

### 5.2 两项质量指标

| 指标 | 含义 |
| --- | --- |
| 背景透明率 | 四条边框区域被透明化的比例，越高越干净 |
| 主体保留率 | 被判为主体的像素占比，突然大幅下降说明主体被误删 |

## 6. 已知限制

1. **白色主体部件贴白底**（白色裙子、衣领、头纱）：这是纯颜色方法的原理天花板——
   它们和背景颜色一样，算法分不出哪块是背景。
   → 默认走**混合引擎**会自动用 AI 补回来（能看到"AI 补齐同色主体部件 x.x%"提示）；
   个别补不全的地方，用**「点选」涂保留**或**「描边」+ 保留**，一劳永逸。
2. **模型都随包预置，无需联网**：
   - u2netp.onnx（约 4.5MB）：混合 / AI 引擎用；
   - birefnet_tiny.onnx（约 224MB）、isnet.onnx（约 178MB）：**精细抠图**引擎用。
   三者都在 `src/models/models/` 下，也打进了 exe。引擎不依赖 rembg，
   只要能 `import onnxruntime` 就能用；不可用时界面会明确告诉你缺什么（缺库 / 缺模型文件）。
   > 也因此**打包后的 exe 约 463MB**（含 400MB 模型），这是正常的，不是异常膨胀。
3. **AI 的盲区**：u2netp（混合 / AI 引擎）偶尔会"漏认"主体（只认出局部）。混合引擎已做保护——
   AI 判为背景的地方一律沿用颜色键控的结果，不会被 AI 带偏。若仍不满意，
   可切到「精细抠图」，或用**矩形框 / 描边 / 套索**手动指定主体。
4. **发丝级精度**：u2netp（320×320）对头发丝等精细边缘无力，会糊成团块。
   **改用「精细抠图」（BiRefNet 1024×1024）后，发丝、飘带、细长道具都能清晰保留**；
   仍不完美处可再用手动描边精修。代价是单张约 8~17 秒。
5. **手动裁决层是逐图的**：换一张图就会清空，不会串到下一张上。
6. **精细抠图较慢且更吃内存**：复杂图单张 8~17 秒、峰值内存约数 GB；
   如果只是批量处理纯色底图片，用「颜色键控」或「混合」会快得多。
7. **纯色底（白/黑）的"内部白/黑块"是按拓扑保留的，不是按语义**：
   算法判断"某块白该不该删"用的是**它能不能连通到画面边缘**——
   被主体完全包住的内部块（如白裙衬里、眼白）会**保留**；
   只要有一条（哪怕很细的）近白通路连到边框，就会被**当作背景删除**。
   > 典型现象：用 **ROI 框住人物**去跑白底，框边那圈白**仍可能不被去除**——
   > 因为它属于"与边框连通的背景"，判定在**整图阶段**就完成了，框选不改变结论
   > （ROI 是整图推理、只取框内结果，见 3.10）。
   → 想强行去掉，用 **「点选」/「描边」选「去除」**直接裁决（裁决层优先于算法、
   一定生效）；或把「软阈值下界」调小（如 15~20），但会全局生效、可能误删主体浅色部件。

## 7. 常见问题（FAQ）

**Q：直接运行报 `the following arguments are required: -i/--input`？**
A：那是命令行入口 `src.main` 的提示。桌面软件请运行 `src/app`（见第 2 节方式 A）。

**Q：AI 模式提示不可用？**
A：AI 不依赖 rembg，通常无需安装任何东西。看提示里写的**具体原因**：
   - 「缺少 onnxruntime」→ `pip install onnxruntime`（清华源可加
     `-i https://pypi.tuna.tsinghua.edu.cn/simple`）；
   - 「未找到本地模型 u2netp.onnx」→ 模型应位于 `src/models/models/u2netp/`，丢了请找回；
   - 若只是没装 AI，把引擎切到**颜色键控**仍可正常使用。

**Q：以前双击 exe 选 AI 会报"请安装 rembg 与 onnxruntime"，现在还这样吗？**
A：不会。这是已修掉的缺陷——程序已自己实现推理，不再需要 rembg/scipy，
   用重新打包的 `dist/LucentCut.exe` 即可。

**Q：为什么现在处理复杂图要十几秒？**
A：默认引擎「精细抠图」用的是 BiRefNet 大模型（1024×1024），质量高但**CPU 上单张约 8~17 秒**，
   属正常。追求速度可在「处理方式」里切到「混合」或「颜色键控」（0.2~1 秒）；
   **纯色底图片即使选「精细抠图」也会自动走颜色键控，同样是 0.2~0.3 秒**。

**Q：我选了「精细抠图」，但状态栏显示 `hybrid-white`，是不是没生效？**
A：生效了，这是**有意设计**。纯色背景用颜色键控的轮廓比任何语义分割都更贴合原始像素，
   所以精细引擎检测到纯色底会自动改用颜色键控（快且准）。只有复杂背景才会真正调大模型，
   那时状态栏显示 `matting`。

**Q：exe 怎么突然变成 440 多 MB 了？**
A：v1.5 起把 BiRefNet（224MB）+ ISNet（178MB）两个大模型打进了包，所以体积从约 45MB 涨到约 463MB。
   换来的是复杂图发丝级精度。模型全部离线、无需联网。

**Q：图片太大看不全，描边时很别扭？**
A：滚轮放大，然后**按住鼠标中键拖动**画面（触摸板用 Ctrl+左键拖动）。
   拖动画面不会动到你已经画好的线。按 Ctrl+0 可以随时回到整图视图。

**Q：描错了怎么办？**
A：按 Ctrl+Z。第一下退掉刚点的那个顶点，再按退掉整块（会变回未闭合状态可以继续改），
   再按撤销上一次已经生效的修改。不用从头重画。

**Q：我想一次保留好几个地方？**
A：直接连续描多块：闭合一块后接着画下一块，最后按 Enter 一起生效。

**Q：先自动处理、再描了保留区、又点了一次「开始处理」，保留还在吗？**
A：**在。** 手动的保留/去除是独立保存的裁决层，永远在算法跑完后叠加，
   优先于算法结果。想去掉它点「清除手动修改」。

**Q：我描了保留区，为什么边缘看起来有点透？**
A：那是边界的柔化（默认 1 像素）。想要硬边就把「手动区边缘柔化」调到 0。
   区域内部始终是 100% 不透明的。

**Q：处理完了，结果图上还压着一块绿色的描边？**
A：v1.3 已修好——「显示修改区」现在**默认关闭**，应用/处理完之后只显示结果本身。
   想回看自己标过哪些地方，勾上它再看。

**Q：点了「点选」在眼睛上点绿点，保存后眼白还是被去掉了？**
A：两点注意：① 点完之后要按 **Enter** 或点 **「✔ 应用选区」**，
   不应用是不会生效的；② 点选现在是**笔刷**，按住左键拖动能把一片都涂上，
   太小的话把「点选笔刷半径」调到 5~8 并放大画面再涂。
   涂完在状态栏能看到"保留 xxxx px"，就说明生效了。

**Q：「应用选区」按钮到底是干什么的？为什么我一按整张图都变透明了？**
A：那是旧版的坑，v1.3 已修。「应用选区」= 把你画的保留/去除**直接盖章生效**，
   涂哪儿改哪儿，不会动其它地方。
   旧版把它和 GrabCut 自动抠图混在一个下拉框里、默认还是 GrabCut，
   点几个点再应用就等于让算法全局重抠，才会整图变透明。
   现在 **GrabCut 是独立按钮，且必须先画出区域**；没画区域时点它只会提示，不会破坏结果。

**Q：什么时候该用「应用选区」，什么时候该用「GrabCut 自动抠图」？**
A：想**补/删某一块**（衣服被删、背景没去净）→ 「应用选区」；
   想**让算法把整张图重新抠一遍**（换个更好的主体范围）→ 先画个大范围的框/描边，
   再点「GrabCut 自动抠图」。

**Q：处理完某个浅色细节（眼睛高光、白色围裙）看起来发灰、半透明，像蒙了一层雾？**
A：v1.4 已修。原因是这些浅色部件与背景色差很小，落在软阈值过渡带里，
   旧算法把它们当成了"既非前景也非背景"的中间像素，永久保留成半透明。
   现在凡是在主体内部（不与画面边框连通）的像素一律恢复成完全不透明，
   但**主体轮廓边缘的柔和过渡保持不变**（不会变硬边）。
   如果你希望边缘更锐利，可把「软阈值上界」调小到 40~60。已在 `deepseek.jpg`
   眼睛高光、`doro1.png` 白裙上实测修复。

**Q：批量处理会中断吗？**
A：不会，失败的图会跳过并记录，其余继续。批量不套用当前这张图的手工裁决。

**Q：纯色底的人像图，为什么「AI 语义分割」反而比「精细抠图」保留得多？**
A：正常现象，两引擎"谁多谁少"都说得通，不是 bug：
纯色底时精细引擎会自动落回颜色键控（状态栏显示 `hybrid-white` 等），它删掉的
是**和背景色几乎一模一样**（色差 <5）的像素——从抠图角度这是"对"的；
u2netp 因为分辨率低（320×320），把这些边缘像素糊成了半透明前景，看起来
"保留更多"，其实边缘是虚的。反之在复杂背景里，精细引擎（1024×1024）能分辨
人物手臂之间**真实透出的背景缝隙**，u2netp 会把这些细缝糊成前景。
结论：**纯色底两者都对、按喜好选；复杂背景要精确轮廓选精细，要"整块保住
不怕糊"选 AI 语义**，缝隙/边缘差异属于两个模型的正常分工。

**Q：白底图我用 ROI 框住人物去处理，为什么框里那圈白背景还是没去掉？**
A：这是白底算法的**正常行为，不是 ROI 失效**。白底抠图判断"某块白要不要删"用的
是**拓扑依据——它能不能连通到画面边缘**，不是语义：
- 被主体完全包住的白块（白裙衬里、眼白）→ **保留**；
- 与画面边缘连成一片的白背景 → **删除**。

ROI 的处理方式是"**整图跑一遍算法、只取框内的结果**"，所以框内那块白到底删不删，
取决于它在**整图上**的连通判定，**框选本身不会改变这个判定**。
你截图里框边那圈白，很可能是与边框连通的背景块的一部分（只是被框线切了一角）。
→ 想强行去掉：用 **「点选」/「描边」选「去除」**直接裁决（裁决层优先于算法，一定生效）；
或把「软阈值下界」调小到 15~20（会全局生效，注意别误删主体浅色部件）。
